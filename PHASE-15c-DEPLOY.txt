Phase 15c — Add-on qty + modifier suffix

═══════════════════════════════════════════════════════
WHAT'S NEW
═══════════════════════════════════════════════════════

Two improvements to the add-on system from Phase 15b:

1. Add-ons now support quantity. "Add 2 5x7s" can be mapped to
   SKU 10 with qty=2, and the synthesized line item will have
   qty 2 — flowing correctly through imposition, slip counts,
   and Darkroom .txt.

2. Add-ons now support a "modifier" type. Instead of synthesizing
   a new production line, a modifier appends a suffix to the
   parent line's product name (e.g. " (Framed)") so the suffix
   prints on:
     - the Darkroom .txt's item description (visible on the print)
     - the packing slip (with a yellow highlight)
   The customer-paid fee tracks against the parent's options list
   (visible) but doesn't drive any production routing.

═══════════════════════════════════════════════════════
CONFIG SCHEMA (addon-mappings.json)
═══════════════════════════════════════════════════════

Old (Phase 15b):
  "2007": { "name": "...", "sku": "..." }

New (Phase 15c):
  Product type:
    "2007": { "type": "product", "name": "...", "sku": "...", "qty": 2 }

  Modifier type:
    "2050": { "type": "modifier", "name": "Frame", "suffix": " (Framed)" }

Legacy entries without an explicit type field continue to be
treated as product (backward-compatible). The Settings UI shows
type-aware editors.

═══════════════════════════════════════════════════════
KNOWN LIMITATION
═══════════════════════════════════════════════════════

If a single line item has MANY modifiers, the slip's yellow
highlight line can overflow horizontally. Layout calc estimates
character width and clips to the available space. If you hit a
case where it's truncated, let me know and I'll adjust to wrap
or use smaller text.

The .txt suffix path is the same as the productName so no width
concerns there.
