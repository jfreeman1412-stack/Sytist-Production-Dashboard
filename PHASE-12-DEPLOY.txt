Phase 12 — order detail page polish + logo warning

═══════════════════════════════════════════════════════
THREE THINGS
═══════════════════════════════════════════════════════

1) UN-WATERMARKED THUMBNAIL ON ORDER DETAIL PAGE

   The line item thumbnail on the order detail page was using
   photo.thumbUrl (watermarked). Switched to fullUrl first,
   falling back through largeUrl → thumbUrl. Same fix that
   went into the override editor pickers (Phase 11i).

2) REMOVED "GENERATE TEAM DIVIDERS" CHECKBOX

   Dividers are a batch-printing concept — they separate teams
   when multiple orders print together. At the single-order
   level they don't apply, so the checkbox was confusing UI.
   Removed from ProcessOrderBlock; server defaults the flag
   to false when absent. The dividers FEATURE is preserved
   server-side for the future multi-order batch flow.

3) LOGO WARNING BANNER

   New banner on the order detail page (just below the Process
   block) that warns if the order's gallery has no logo set.
   Catches "operator forgets to upload a logo, then renders a
   batch of composites with placeholder logos" before any work
   gets wasted.

   Mechanism:
     - New server endpoint: GET /api/sytist/gallery-assets/logos/
       :galleryId/exists → { exists: boolean, filename? }
       Cheap — just checks meta, no image bytes.
     - Client component LogoWarningBanner calls the endpoint
       on mount. Renders nothing while loading, on error, or
       when logo exists. Shows a red-bordered banner when the
       logo is definitively missing.
     - Banner text: "No logo set for this gallery. Any composite
       that uses a logo slot will render a 'no logo' placeholder.
       Upload one at Settings → Gallery Assets before processing
       if a logo is expected."

   Why a banner, not a confirm dialog:
     - The banner is visible from page load — operator catches
       it the moment they open the order, not at click time
     - Doesn't add extra mouse trips for orders where the logo
       is intentionally absent (rare but possible)
     - The Process result already shows composite_missing_logo
       warnings after-the-fact, so this is just earlier signal
       not a hard block
