Phase 9e-hotfix2 — fix browser cache showing stale graphics

═══════════════════════════════════════════════════════
THE BUG (now diagnosed)
═══════════════════════════════════════════════════════

Your most recent screenshot shows the canvas rendering a cloudy-
gray-and-green image. But the file you uploaded (Generic_MM2025.png)
is a black memory-mate frame on a watercolor background. They don't
match.

Diagnosis: the browser is showing a cached PREVIOUS upload's pixel
data at the URL `/preview?v=N`, even after you re-uploaded a
different image at the same key. Two contributing factors:

1. The preview endpoint set 'Cache-Control: no-cache', which —
   confusingly — does NOT mean "don't cache." It means "you may
   cache, but you must revalidate before serving." With no
   Last-Modified or ETag headers on the response, the browser
   may decide to serve the cached copy without revalidating.

2. The client used a render-counter `graphicsBust` as the URL's
   cache-buster. The counter increments after every library
   refresh, but if the render hasn't completed when the counter
   bumps, the URL might not actually change between renders.

═══════════════════════════════════════════════════════
THE FIX
═══════════════════════════════════════════════════════

SERVER:
  Cache-Control: 'no-store, no-cache, must-revalidate, max-age=0'
  + Pragma: 'no-cache' + Expires: '0'
  Browsers are required to make a network request every time —
  no shortcut to a cached copy ever.

CLIENT:
  Cache-buster URL is now built from the file's `uploadedAt`
  timestamp and `sizeBytes` from the library metadata. So the
  URL changes if and only if the file on disk actually changed.
  Re-uploads at the same key get a new URL automatically.

═══════════════════════════════════════════════════════
ALSO: DO A HARD REFRESH AFTER DEPLOY
═══════════════════════════════════════════════════════

The cache headers don't retroactively clear what's already in
the browser cache from BEFORE this fix. After deploying:

  1. Reload the dashboard
  2. Press Ctrl+Shift+R to force a full reload (bypassing cache)
  3. Or open DevTools → Network tab → check "Disable cache" while
     DevTools is open

After that one-time hard refresh, future re-uploads will refresh
correctly without manual intervention.
