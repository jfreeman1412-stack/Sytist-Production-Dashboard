Phase 11a — fix blank page bug + in-editor order switcher

═══════════════════════════════════════════════════════
WHAT THIS FIXES
═══════════════════════════════════════════════════════

BUG: blank page after clicking a line item from the picker.

Root cause: response shape mismatch. The composite layout GET
endpoint returns the layout directly (`res.json(layout)`), but my
Phase 11 OverrideEditorPage expected `{ layout: ... }`. Result:
the layout state stayed null, the editor's render guard returned
null, blank page. No error banner because no error was thrown —
just a silent null.

Fix:
  - Treat the response as the layout itself
  - Use `layoutResp.id` as the validity check
  - If the response shape really is broken (defensive), set an
    error instead of going blank
  - The final fallback render no longer returns null — it shows a
    "could not load" banner with a back button, so any future
    silent-null bug is visible instead of invisible

ALSO ADDED: in-editor order switcher.

Before: to fix another order, you had to navigate "Back to order
picker" → type new order → load → click line item. Four clicks.

Now: a collapsible "Switch to a different order" section at the
top of the editor. Type order ID, click Load, see line items, click
one. Two clicks if it's already expanded. The editor re-mounts
with the new params automatically.
