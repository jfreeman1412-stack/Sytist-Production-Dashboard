Phase 11e — un-watermarked player photo + correct layer order during drag

═══════════════════════════════════════════════════════
TWO BUGS FROM YOUR SCREENSHOT
═══════════════════════════════════════════════════════

BUG 1: Watermarked player photo.
  The live overlay was using `largeUrl` from the line item. Turns
  out `largeUrl` is the watermarked version (Sportsline Photography
  watermark across the player). Operators were dragging a
  watermarked photo around — confusing about what the actual render
  will look like.

  Fix: Switch to `fullUrl` (the un-watermarked original). May be
  2-5MB but loads once and the browser caches it; subsequent
  drag/scale is instant from cache. The composite engine also uses
  `fullUrl` for the real render, so we're now using the same
  source image.

BUG 2: Player photo drawing ON TOP of graphics/logos/text.
  The live overlay rendered the player at its slot's SVG position,
  but it appeared above other slots that were SUPPOSED to be layered
  on top in the JSON order. Why: in backdrop mode, the canvas
  suppresses inline rendering for graphics, logos, and text (they're
  "already in the backdrop"). So the live player overlay paints
  onto an effectively empty SVG layer with no graphics/text/logo
  pixels above it to cover the player as it moves.

  Fix: When live overlays are active (i.e., the override editor is
  using the canvas), the canvas ALSO renders inline:
    - Static graphics (already had URLs)
    - Logo (new — passed via logoUrl prop, fetched from the
      existing public gallery-assets/logos preview endpoint)
    - Text content (already had the text in slot.text — just
      stopped suppressing it)

  With those all rendering at their slot positions in JSON array
  order, SVG natural paint order handles layering correctly. The
  player photo paints first, then teamPhoto outline, then graphic
  image, then logo image, then text — text on top, player at the
  bottom of the stack.

WHAT YOU'LL SEE
═══════════════════════════════════════════════════════

Drag the player photo:
  - No watermark on the moving photo
  - When you drag it into an area where the graphic, logo, or text
    is supposed to be on top, those elements actually cover the
    player photo as expected
  - Layer order matches what the final composite will look like

The server backdrop still loads underneath as a reference (1.5s
debounce). It refreshes after you stop dragging. But during the
drag, the canvas is fully WYSIWYG via live SVG rendering — what
you see while dragging IS the layer order the render will produce.

HOW TO VERIFY
═══════════════════════════════════════════════════════

  1. Open an override editor with a layout that has BOTH a player
     photo AND a static graphic AND a logo AND text.
  2. The player photo should appear WITHOUT a watermark.
  3. Drag the player photo around the canvas.
  4. When you drag it into the area where the graphic / logo /
     text is positioned, those elements should appear ON TOP of
     the player, not under it.
  5. Layer order in the layers panel matches what you see on
     canvas.
