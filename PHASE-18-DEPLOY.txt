Phase 18 — Path date fix + specialty routing rework

═══════════════════════════════════════════════════════
PROBLEMS FIXED
═══════════════════════════════════════════════════════

1. The {date} token in path templates resolved to order date, not
   today's date. Result: orders processed today but placed days ago
   landed in historical folders (e.g. 2026-05-06, 2026-05-07) when
   today is 2026-05-12. Operator wants today's work in today's folder.

2. Specialty items were routed to a separate basePath
   (Z:\Sytist\__Open Orders\Specialty) and a specialty-only .txt
   was written there. The .txt would fail with "Images for order
   not stable after 30101ms" when waiting for the specialty image
   to settle. And the structure made it harder for the operator
   because an order's output was split across two trees.

═══════════════════════════════════════════════════════
WHAT THIS PHASE CHANGES
═══════════════════════════════════════════════════════

pathsService.js:
  - {date}        → today's date (processing date), YYYY-MM-DD
  - {order_date}  → NEW. The order's placed date, YYYY-MM-DD.
                    Use this if you ever want order-date routing.
  - knownTokens list updated for the Settings UI dropdown
  - Top-of-file docstring updated to explain both tokens

processingService.js:
  - Specialty items now route to:
      <downloadDir>/Specialty/<subfolder>-<orderId>/
    instead of:
      <specialtyBase>/<subfolder>/
    All of an order's output (regular + specialty) lives under
    the same downloadDir/{date}/{sort segments...} tree.
  - The specialty .txt write block is GONE. Darkroom never sees
    specialty items. The lab operator handles them by hand using
    the packing slip (which still lists them with their highlight
    color).
  - Regular .txt still EXCLUDES specialty items (this was already
    the case; nothing changed there).
  - specialty-products.json's basePath field is no longer read.
    The config still has it; it's safe to leave or remove.
  - subResult.specialtyTxtPath still exists in the result shape
    but is always null (backward-compatible with any caller).

═══════════════════════════════════════════════════════
EDGE CASES
═══════════════════════════════════════════════════════

  - Specialty item with no configured subfolder: falls back to
    the SKU number, e.g. "Specialty/26-110643/"
  - Subfolder name with special characters (e.g. slashes,
    quotes): sanitized to underscores before being used as a
    folder name
  - Orders with no orderNumber AND no orderId: falls back to
    just "<subfolder>" (no -orderId suffix). Shouldn't happen
    in practice.
  - Empty orderDate from MySQL: {order_date} falls back to today
    (preserving the old fallback behavior of _extractDate)
