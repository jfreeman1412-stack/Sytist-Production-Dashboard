NEW ENDPOINTS
═══════════════════════════════════════════════════════

POST /api/sytist/process/order/:orderId
   Body: { generateDivider?: boolean }
   Synchronously processes one order. Returns full result with every
   sub-order's outcome.

POST /api/sytist/process/batch
   Body: { orderIds: string[], generateDivider?: boolean, generateQrSheet?: boolean }
   Kicks off a batch job, returns jobId immediately. Cap 500 orders.

GET  /api/sytist/process/job/:jobId
   Polls a batch job's progress.

GET  /api/sytist/process/settings
PUT  /api/sytist/process/settings   (admin)
   Body: { autoStatusUpdate, targetStatusId }

GET  /api/sytist/specialty/config
PUT  /api/sytist/specialty/base-path           (admin)
PUT  /api/sytist/specialty/highlight-colors    (admin)
POST /api/sytist/specialty/products            (admin)
PUT  /api/sytist/specialty/products/:externalId (admin)
DELETE /api/sytist/specialty/products/:externalId (admin)

WHAT TO VERIFY
═══════════════════════════════════════════════════════

CHECK PATH MODE FIRST — go to Settings > Paths and confirm mode is "test".
DO NOT verify in production mode. The orchestrator writes real files,
which Darkroom will pick up if those paths are watched.

1. PER-ORDER PROCESS BUTTON:
   - Open any order detail page (Phase 4.5+ orders should work).
   - You'll see a new "Process this order" card right below the header strip.
   - For sibling non-home orders, a "Generate team dividers" checkbox appears.
   - Click "Process this order" — confirm dialog, then watch the result inline.
   - Verify files exist at the printed paths (test sandbox).

2. BATCH PROCESSING:
   - Go to /orders.
   - You'll see a new selection action bar above the table and a
     checkbox column on each row.
   - Select 2-3 orders via checkboxes. Click "Process selected (N)".
   - Modal appears with two options: "Generate team dividers" and
     "Generate QR sheet". Click Start.
   - A floating progress banner appears bottom-right. Watch it tick
     through each order. Final state shows success/partial/failed counts.
   - Try "Process all filtered" too — confirms it pulls every matching
     order into the batch.

3. SPECIALTY PRODUCTS:
   - Go to Settings > Specialty.
   - The list will be empty. Add a real specialty SKU from your catalog
     (e.g. an acrylic SKU). Subfolder defaults to product name.
   - Open an order containing that SKU. Look at the slip preview —
     specialty rows should now show an orange tint and a "SPECIALTY"
     badge in the corner.
   - Process the order. Specialty items should land in basePath\subfolder
     instead of the regular order folder. A separate "*_specialty.txt"
     gets written for them.

4. AUTO STATUS UPDATE:
   - Go to Settings > Processing.
   - Toggle "Update order status after successful processing" ON.
   - Pick a target status (e.g. "40 - Printing and Production").
   - Save.
   - Process an order. After successful processing, check Sytist —
     the order's status should now be 40.
   - Toggle it back OFF before exiting if you don't want this to fire
     during routine verification.

═══════════════════════════════════════════════════════
SAFETY NOTES
═══════════════════════════════════════════════════════

- The .txt is written LAST. Every other artifact (downloads, imposed
  sheets, slip, divider) lands first. If anything earlier fails, the
  .txt either doesn't get written or excludes the failed line.

- Atomic .tmp + rename for every write. The Darkroom watcher never sees
  a half-written file.

- Continue-on-error: if a single photo fails to download, the line item
  is dropped and a warning surfaces; the rest of the sub-order completes.
  PARTIAL OUTPUT WILL BE SENT TO DARKROOM. Operator sees the warning
  in the result UI and handles the missing photo manually.

- Sibling chunking: ship_to_managers and ship_to_league orders split
  per-team. Each team gets its own slip, divider (if enabled), and .txt.
  ship_to_home siblings stay as one bundle.
