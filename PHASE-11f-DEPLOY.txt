WHAT WAS BROKEN IN YOUR SCREENSHOT
═══════════════════════════════════════════════════════

TWO BUGS:

1) DOUBLE TEXT: "Sample Player" appeared twice, slightly offset.
   The server-rendered backdrop had baked-in text, AND my live
   SVG was rendering the text again. SVG and server use different
   fonts/anti-aliasing, so the duplicates didn't perfectly
   overlap → visible ghosting.

2) PLAYER PHOTO LAYERING: even with my Phase 11e fix that
   rendered graphics inline above the player, you noted the
   player still appeared above the graphic. The fix was working
   for graphics/logos/text rendering, but in your screenshot
   the player happens to be in an area where the graphic doesn't
   exist, so the layering wasn't actually being tested. The
   true latent bug was the doubling.

═══════════════════════════════════════════════════════
THE FIX: REMOVE THE BACKDROP ENTIRELY
═══════════════════════════════════════════════════════

The override editor no longer fetches the server-rendered
composite backdrop. Instead, the canvas renders EVERYTHING via
live SVG elements:

  - playerBackground: <image> via lineItem.backgroundPhoto.fullUrl
  - playerPhoto:      <image> via lineItem.photo.fullUrl
  - teamPhoto:        <image> via team-photo lookup endpoint
                      (NEW: fetched on editor mount via
                      /api/sytist/team-photo/lookup)
  - staticGraphic:    <image> via per-layout graphics preview
                      (NEW: computed from layout.graphics map)
  - logo:             <image> via /gallery-assets/logos/.../preview
  - text:             native <text> via existing SlotText
                      component, with token substitution

These all paint in JSON array order (slots[0] first, slots[N]
last). SVG paint order means later = on top. So if the layout
has the player photo at index 1 and the static graphic at
index 3, the graphic naturally paints over the player photo
in the SVG output — same as the production composite.

With nothing baked into a backdrop, there's no doubling.
Layer order is automatic. WYSIWYG.

═══════════════════════════════════════════════════════
TRADE-OFFS
═══════════════════════════════════════════════════════

WHAT WE LOSE:
  - The server-rendered backdrop served as a visual sanity check
    of what the actual composite will look like. Pixel-for-pixel
    fidelity (colors, font rendering, sharp's resize quality)
    is now an estimate based on SVG behavior. For positioning
    work, SVG is plenty accurate; for color/font fidelity
    confirmation, operators trust the layout designer's preview
    or the actual produced file after Apply.

  - Reduced server load — we no longer fire a /composite/preview
    on every layout change in the override editor. Apply still
    does a server render. The editor session is now mostly
    self-contained client-side until Apply.

WHAT WE GAIN:
  - No double-rendering of text/graphics/logos
  - Instant response on every edit (no 1.5s debounce wait, no
    5-10s server render)
  - Correct layering automatically (SVG paint order = JSON layer
    order)
  - Lower server load
  - No watermark issues (we control everything that renders)

═══════════════════════════════════════════════════════
KNOWN LIMITATIONS
═══════════════════════════════════════════════════════

- SVG TEXT RENDERING isn't pixel-identical to the server's
  sharp/canvas text rendering. Font may be slightly different,
  line-height may differ, kerning may differ. For positioning,
  it's accurate. For pixel-perfect typography preview, trust the
  final output file.

- LIVE URLS REQUIRE NETWORK FETCHES — the full-resolution player
  photo (~2-5MB) downloads when the editor opens. Subsequent
  drag is instant from cache.

- IF THE TEAM PHOTO LOOKUP FAILS (no sub-gallery, network error,
  etc.), the team photo slot renders as a placeholder rect with
  the slot's color/label, not the actual team image. Editor
  still works; operator can position the slot but won't see the
  team's actual photo. Same fallback applies to any missing URL.
