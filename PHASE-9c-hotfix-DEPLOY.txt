Phase 9c-hotfix — fix React rules-of-hooks violation in designer

═══════════════════════════════════════════════════════
THE BUG
═══════════════════════════════════════════════════════

After deploying 9c, the dashboard failed to compile with:

  ERROR in [eslint]
  src\pages\settings\LayoutDesignerPage.js
    Line 489:24:  React Hook "useMemo" is called conditionally.
    React Hooks must be called in the exact same order in every
    component render. Did you accidentally call a React Hook
    after an early return?  react-hooks/rules-of-hooks

Diagnosis: I added the `graphicsUrls` useMemo BELOW the early
returns for `loading`, `error`, and `!layout` states. On the
first render (before the layout had loaded), the early return
fired, so useMemo never ran. On the second render (layout
loaded), useMemo ran for the first time. React's hook tracking
detected the order change and threw.

═══════════════════════════════════════════════════════
THE FIX
═══════════════════════════════════════════════════════

Moved the `graphicsUrls` useMemo to BEFORE the early returns.
Hooks must run in the same order on every render — that's the
core invariant of React's hook system. The memo's dependencies
(layoutId from useParams, graphicsLibrary and graphicsBust from
state hooks) are all defined above its new position.

WHY THIS WASN'T CAUGHT EARLIER
═══════════════════════════════════════════════════════

Honest answer: my smoke tests render the COMPONENTS in isolation,
not the full page through React's runtime. ESLint's rules-of-hooks
linter only fires during a real React build (npm run dev /
webpack). That's the gap.

I should have either:
  1. Run the lint check as part of my smoke tests, OR
  2. Mentally audited "are all hooks above early returns?" before
     bundling

Going forward I'll add the manual audit step. Sorry for the
roundtrip.
