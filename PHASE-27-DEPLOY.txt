Phase 27 — Imposition WYSIWYG editor (ported from PhotoDay dashboard)

═══════════════════════════════════════════════════════
WHAT THIS DOES
═══════════════════════════════════════════════════════

Replaces the JSON-textarea modal in Settings → Imposition with a
proper form-driven editor and live SVG preview, ported from the
older PhotoDay dashboard at sportsline-dashboard/.

The editor has:
  - Form fields for all geometry: name, cols, rows, item dims,
    sheet dims, DPI, col/row gaps, center-on-sheet toggle, left
    and top margin
  - Text-overlays sub-editor — repeating cards with text content,
    position (X/Y), optional W/H, font size, rotation, color,
    auto-size, center-align
  - Variable insertion buttons that pull from
    /api/sytist/imposition/text-variables (same endpoint Sytist
    already exposed)
  - Live SVG preview on the right showing:
      - sheet (white)
      - grid cells (blue)
      - gap regions (red, faint)
      - left/top margins (green, faint)
      - extra space beyond grid (orange, faint)
      - text overlay anchors (color-coded dashed boxes)
      - ruler ticks along top and left edges
  - "Live" — every edit re-renders the preview immediately

Schema is unchanged. JSON payload sent to the server is identical
to what the old JSON textarea produced. Old imposition layouts
load and edit correctly. Backward-compat: layouts that use the
legacy single `gap` field get migrated to colGap/rowGap on first
load.

═══════════════════════════════════════════════════════
KNOWN LIMITATIONS
═══════════════════════════════════════════════════════

  - No drag-on-canvas for text overlays. You enter X/Y via inputs.
    The PhotoDay editor was also numeric-input-only for overlays —
    just with a visual preview to confirm positions. Same pattern
    here.
  - The preview is a simplified visualization, not a pixel-perfect
    render. The actual rendered output uses impositionService on
    the server side which knows about colors, fonts, etc.
  - No "Raw JSON" escape hatch in the new editor. If you need to
    edit a field that the editor doesn't expose, the API still
    accepts the full JSON shape — you can POST/PUT directly. (Or
    I can add a Raw JSON expandable section in a follow-up if
    that's useful.)
