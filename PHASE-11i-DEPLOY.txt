Phase 11i — un-watermarked + bigger thumbnails in pickers

═══════════════════════════════════════════════════════
WHAT THIS FIXES
═══════════════════════════════════════════════════════

In 11h I bumped picker thumbnails to 88px (landing) and 72px
(switcher), but I sourced them from `li.photo.largeUrl` —
which is the watermarked version. Same mistake I made in the
override editor in 11d that I fixed in 11e. Pattern:
"largeUrl" sounds like a sensible default but it's always the
watermarked one. fullUrl is the un-watermarked original.

═══════════════════════════════════════════════════════
THE FIX
═══════════════════════════════════════════════════════

  1. Thumbnail source: fullUrl first, fall back through
     largeUrl → thumbUrl. Same approach the override editor
     canvas uses for the live overlay.

  2. Bigger sizes:
     - Landing page: 88px → 140px (square thumb tile)
                     padding 14/16 → 16/18, gap 16 → 18
     - In-editor switcher: 72px → 110px
                     padding 12/14 → 14/16, gap 14 → 16

═══════════════════════════════════════════════════════
COST/BENEFIT
═══════════════════════════════════════════════════════

The fullUrl is the original photo (~2-5MB per item). For an
order with 6 line items, that's potentially 12-30MB of image
downloads when the operator clicks Load. In practice:
  - Browsers parallel-fetch images, so it's fast
  - Browser caches per URL, so re-loads are instant
  - Most operators load 1-3 orders per session

Operators get un-watermarked, big-enough-to-see thumbnails.
The bandwidth tradeoff is worth it.
