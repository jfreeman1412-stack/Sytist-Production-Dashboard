Phase 11h — Enter-to-load + larger picker UI

═══════════════════════════════════════════════════════
TWO IMPROVEMENTS
═══════════════════════════════════════════════════════

1) ENTER KEY TRIGGERS LOAD

   On both the OrderOverridesPage landing page AND the
   in-editor "Switch to a different order" panel, pressing
   Enter inside the Order ID field now triggers Load — same
   as clicking the button. The landing page's Order ID field
   also receives autoFocus so the operator can land on the
   page and just start typing.

   Saves a mouse trip on every order lookup. Operators run
   this flow repeatedly when working through overrides for
   different orders.

2) LARGER PICKER UI

   The "Find an order" card and the line items list were
   small and cramped. Bumped up:

   - Order ID input:   fontSize 13 → 16, padding 8 → 10/12
   - Load button:      fontSize 13 → 15, padding 8/14 → 11/22
   - Line item rows:   thumbnails 56→88px (landing) / 44→72px (switcher)
                       padding 10/12 → 14/16
                       gap 12 → 16
   - Item title:       fontSize 13 → 16 (landing) / 12 → 15 (switcher)
                       added 3px bottom margin so subtitle has air
   - Item subtitle:    fontSize 11 → 13 (landing) / 10 → 12 (switcher)
   - "OVERRIDE" badge: fontSize 10 → 12, more padding
   - Chevron (›):      fontSize 18 → 22 (landing)
   - Hint text:        fontSize 12 → 13, hint mentions Enter

   The line items list in the switcher also got a higher
   maxHeight (320 → 400) since rows are taller.

   Thumbnails now use largeUrl preferentially since thumbUrl
   at the larger sizes scales poorly. largeUrl is bigger but
   still fast enough at this resolution.
