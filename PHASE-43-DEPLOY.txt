Phase 43 — Composed thumbnail cache + Push Packaging resilience
═══════════════════════════════════════════════════════

WHAT THIS DELIVERS
─────────────────────────────────────────────

Five related fixes, all related to making the
"Send to ShipStation" button on the order detail card
work as well as the regular Process flow.

  1. NEW SQLite cache for composed thumbnail URLs.
     Process Step 1.4 writes them; Push Packaging reads
     them.

  2. Push Packaging hydrates composedImageUrl on each
     line item from cache, so the SS payload sends the
     composed thumbnail URL (not the raw keyed-out PNG).

  3. orderDate ISO 8601 conversion. Sytist's MySQL
     returns DATETIME as "YYYY-MM-DD HH:MM:SS" (with
     space) which ShipStation rejects with a confusing
     404. Now converted via new Date(...).toISOString().

  4. Push Packaging pre-checks via listOrders before
     attempting an UPDATE. If the linked SS order no
     longer exists (operator deleted it), automatically
     switches to fresh-create instead of trying to
     update a tombstoned record.

  5. Belt-and-suspenders: if the UPDATE call returns
     404 anyway (race condition between pre-check and
     push), auto-retry as fresh create.

PLUS: keeps the Phase 42 hotfix 1 diagnostic logs in
processingService and sytistDbService — so we'll
finally get the per-cart greenscreen state in the log
when you next reprint an order.

WHY THE CACHE IS NECESSARY
─────────────────────────────────────────────

composedThumbnailService.publish() returns a URL after
uploading a composed JPEG to S3 (or wherever). Today
that URL is mutated onto the line item as
li.composedImageUrl for the duration of one
processOrder call.

But the "Send to ShipStation" button on the order
detail card is a different route handler:
  - Reads order state fresh from Sytist
  - Builds SS payload
  - Does NOT run Step 1.4 (no compose, no upload)

Without a cache, this button never sees previously
uploaded thumbnail URLs and always falls back to the
keyed-out PNG.

The cache stores the URL keyed by (orderId, cartId)
during Process, so Push Packaging can hydrate before
building the payload.

WHAT'S IN THIS TARBALL
─────────────────────────────────────────────

NEW FILES (1):

  server/services/composedThumbnailCacheService.js
    - SQLite-backed (orderId, cartId) → URL map
    - upsert(), listByOrder(), getUrl(), deleteByOrder()
    - Uses same sytist-dashboard.db as other services
    - Auto-creates table on first init

MODIFIED FILES (5):

  server/services/processingService.js
    + Imports composedThumbnailCacheService
    + Step 1.4: after publish(), upsert() the URL into
      the cache (non-fatal on failure)
    + Keeps the Phase 42 hotfix 1 diagnostic log

  server/services/shipstationService.js
    + orderDate conversion via new Date(...).toISOString()
      with try/catch fallback to current time on parse
      failure
    + Logs a warning if the input couldn't be parsed

  server/services/schedulerService.js
    + After successful Sytist sync to shipped, ALSO
      clears the SQLite cache rows (in addition to the
      Phase 42 S3 cleanup)

  server/routes/sytist.js
    + push-packaging route: hydrate li.composedImageUrl
      from cache before buildOrderFromSytist
    + push-packaging route: listOrders pre-check by
      orderNumber; if not found, switch to fresh-create
      mode without orderId
    + push-packaging route: if SS returns 404 on UPDATE
      anyway, auto-retry as fresh create
    + Adds 'pathTaken' to response: 'update' |
      'fresh_create' | 'fresh_create_after_404'

  server/services/sytistDbService.js
    + Keeps the Phase 42 hotfix 1 diagnostic log at
      package expansion time
