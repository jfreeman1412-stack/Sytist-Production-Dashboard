Phase 19-v2 — Fix: use flags.package, not flags.isPackageHeader

═══════════════════════════════════════════════════════
WHAT WAS WRONG WITH PHASE 19 v1
═══════════════════════════════════════════════════════

Phase 19 v1 filtered package parent items using
flags.isPackageHeader, but that flag is never actually set on
line items. sytistDbService sets flags.package (when
cart_package > 0) — the canonical marker.

isPackageHeader appears in processingService's SKIP_FLAGS list
as a forward-looking name, but no code ever assigns it. So my
v1 filter was checking a flag that's always undefined → it
filtered nothing → bug unchanged.

═══════════════════════════════════════════════════════
WHAT V2 CHANGES
═══════════════════════════════════════════════════════

packagingService.js — physicalItems filter at line 379 now
checks flags.package (the real marker). Same logic, correct
flag name.

The weight-side filter at line 436 (which was already in place
from Phase 15a) was also using the wrong flag — fixed to match.
This block is now mostly defensive since the upstream filter
catches package items, but consistency matters.
