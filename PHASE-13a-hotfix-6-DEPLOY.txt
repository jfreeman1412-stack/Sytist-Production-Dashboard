Phase 13a hotfix #6 — country code normalization

═══════════════════════════════════════════════════════
WHAT WAS WRONG
═══════════════════════════════════════════════════════

First real Send to ShipStation surfaced this:

  [ShipStation] createOrder 400: The request is invalid.
    apiOrder.billTo.country: Please use a 2 character country code
    apiOrder.shipTo.country: Please use a 2 character country code

Sytist orders store the country as the full name ("United
States") rather than an ISO code ("US"). The original
buildOrderFromSytist was passing the value through unchanged
with just a `|| 'US'` fallback for empty. ShipStation rejects
anything that's not exactly 2 characters.

═══════════════════════════════════════════════════════
THE FIX
═══════════════════════════════════════════════════════

New normalizeCountry() helper at the top of shipstationService.js
that:
  - Returns 2-letter codes unchanged (uppercased)
  - Maps common full-name variants to ISO codes:
      "United States", "USA", "U.S.A.", "America" → US
      "Canada" → CA
      "Mexico" → MX
      "United Kingdom", "UK", "Great Britain" → GB
  - Defaults unknown values to 'US' and logs a warning so we
    notice if a real foreign customer order arrives — the
    warning tells future-you to add the variant to the alias
    map rather than silently mis-shipping

Called from both shipToAddress and billToAddress build steps.

═══════════════════════════════════════════════════════
WHAT'S IN THIS TARBALL
═══════════════════════════════════════════════════════

MODIFIED:
  server/services/shipstationService.js
    + COUNTRY_ALIASES constant + normalizeCountry() helper
    + shipToAddress.country uses normalizeCountry()
    + billToAddress.country uses normalizeCountry()

(No other files. Hotfix-5 still applies for everything else.)

the server log like:

Open server/services/shipstationService.js, find the

needed (require cache holds the module but the map is read on
each call), but you can restart to be safe.
