Phase 20 — Global order search

═══════════════════════════════════════════════════════
WHAT IT DOES
═══════════════════════════════════════════════════════

Adds a search bar at the top of the Orders list page.

Matches against:
  - Order number (exact + partial)
  - Customer name (first + last, concatenated)
  - Email address
  - Phone number (raw and stripped to digits, so "(763) 639-9351"
    and "7636399351" both match)

Behavior:
  - Type ≥ 2 characters → debounced search-as-you-type (250ms)
  - Enter → immediate search; if there's a single exact match
    (especially on numeric order number), jumps directly to the
    order detail page
  - Multiple matches → dropdown list, click or arrow-keys-then-Enter
    to pick
  - Esc → close dropdown
  - × button or empty input → clear
  - Skips current workflow / status filters entirely — search
    results always show, regardless of what the list view is
    filtered to
  - Current filter context is preserved in the URL so the order
    detail page's Back to Orders link returns to the same view

Limited to 10 results. Refine the query for more.

MODIFIED:
  server/services/sytistDbService.js
    Added searchOrders(query) method that runs a single SQL
    query against ms_orders with the standard "paid + non-erased"
    predicate plus the OR'd match clauses. Returns at most 10
    results with stable shape:
      { orderId, orderNumber, orderDate, customerName, email,
        phone, total, productionStatusId, productionStatusName }

  server/routes/sytist.js
    Added GET /api/sytist/orders/search?q=<query> route.
    Registered BEFORE the existing /orders/:orderId route so
    Express doesn't treat "search" as an order ID.

  client/src/pages/OrdersListPage.js
    Added search input above the workflow tabs row.
    React hooks for search state, debouncing, race-condition
    protection. Dropdown UI with keyboard nav, click handlers,
    and per-result rendering (order #, date, customer, email,
    status badge).

═══════════════════════════════════════════════════════
EDGE CASES HANDLED
═══════════════════════════════════════════════════════

  - Empty query: no-op
  - Query of 1 character: no-op (avoids spamming the DB)
  - Stale responses from rapid typing: dropped via current-query
    tracking
  - Click outside the search box: dropdown closes
  - Erased / unpaid orders: excluded (same scope as the list view)
  - Phone with non-digit separators: matches against stripped
    digits too
