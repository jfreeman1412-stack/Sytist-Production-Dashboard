═══════════════════════════════════════════════════════
THE PROBLEM
═══════════════════════════════════════════════════════

Both the Shipping card and the API Keys page were rendering
misleadingly when the /api/shipstation/* endpoints returned 404
(routes not mounted on the server). Both showed an error banner
AND a half-functional UI — Save button with no fields, "Not
eligible" with no real eligibility check.

═══════════════════════════════════════════════════════
THE FIX
═══════════════════════════════════════════════════════

When the load fails AND we have no data to show, render a
dedicated error state with:
  - An explicit "Couldn't load …" banner
  - A helpful diagnosis if the error looks like "Not found"
    (pointing at the missing server/index.js wiring)
  - A Retry button
  - NO half-functional Save button / form
  - NO misleading "Not eligible" fallthrough

═══════════════════════════════════════════════════════
REAL UNDERLYING FIX (still required!)
═══════════════════════════════════════════════════════

The hotfix only improves the error UI. The reason you're seeing
"Not found" is that the server isn't serving /api/shipstation/*.

To fix that, add to server/index.js (look at how /api/sytist is
registered for the pattern):

  await require('./config/appSettings').init();

  app.use(
    '/api/shipstation',
    requireAuth,
    require('./routes/shipstation')
  );

Match the requireAuth import name your project actually uses.
Restart the server, hard-refresh the browser, and the API Keys
page should show form fields for credentials + shipping defaults.
