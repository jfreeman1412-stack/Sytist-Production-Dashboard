Phase 9e — native PNG transparency + per-layer hide/lock

═══════════════════════════════════════════════════════
TWO CHANGES, BOTH DESIGNER-ONLY
═══════════════════════════════════════════════════════

CHANGE 1 — REVERTED 9d's GLOBAL OPACITY HACK
  PNG transparency works natively in browsers. The "see through
  graphics" toggle from 9d was solving a non-problem: it forced
  every static graphic to render at 30% opacity in the designer,
  which is unnecessary because PNG alpha channels already make
  transparent regions transparent. Frame graphics with
  transparent cutouts now show photo slots through the cutouts
  without any tricks — the SVG <image> element respects PNG
  alpha out of the box.

  Removed: the see-through-graphics checkbox from the canvas
  footer toolbar, the global opacity application, the page-
  level state for it.

CHANGE 2 — PER-LAYER HIDE / LOCK (Photoshop-style)
  Each layer card has two new icon buttons before the up/down
  arrows:

    👁 / ⊘   Hide layer    Skips the slot from canvas rendering.
                          Card dims to ~45% opacity so it's
                          still findable in the panel.
    🔓 / 🔒   Lock layer    Slot still renders normally, but you
                          can't drag/resize it on the canvas, and
                          its property editor is replaced with a
                          "Click to unlock" notice.

  Both states are designer-view-only:
    - Not saved to the layout JSON (so they don't bleed into
      production composite renders)
    - Don't persist across page reloads
    - Per-variant — vertical and horizontal have independent
      hide/lock state

  When slots are reordered (drag, ↑/↓) or deleted, the hide/lock
  maps follow — so hiding "the third slot" stays hiding the same
  underlying slot even after reordering.

HOW IT FEELS NOW
═══════════════════════════════════════════════════════

Open a layout with a static graphic that fills the whole sheet
(your frame-with-cutouts case):
  - The graphic renders at full opacity, but the transparent
    regions of the PNG are transparent. Photo slots positioned
    in those transparent regions are visible through the holes.
  - If your graphic is OPAQUE in some area where you need to
    work on a slot underneath, click the 👁 icon on the
    graphic's layer card to hide it temporarily. Click again
    to bring it back.
  - Once a slot is positioned correctly and you don't want to
    bump it accidentally, click 🔓 on its layer card to lock
    it. The slot stays visible in the canvas but mouse drags
    do nothing. Property panel shows a lock notice instead of
    editable fields.

Hide / lock state resets every time you reload the layout. By
design — these are transient view settings, not part of your
layout's permanent definition.

═══════════════════════════════════════════════════════
KNOWN GAPS
═══════════════════════════════════════════════════════

- HIDE / LOCK STATE NOT PERSISTED: every layout reload starts
  with all slots visible and unlocked. If you want this to
  persist (across reloads but NOT to production), localStorage
  would do it. Easy add — tell me if you want it.

- PRODUCTION RENDER ALWAYS USES ALL SLOTS: hidden slots are NOT
  skipped during composite generation in processingService.
  This is intentional — hide is a design-time view aid only.
  If you want a "delete from production but keep in design"
  feature, that's a separate concept (e.g. an "enabled: false"
  flag on the slot itself).

- LOCK ONLY BLOCKS THE CANVAS + EDITOR: arithmetic operations
  like reordering and deleting still work on locked slots from
  the layer-card buttons. Lock prevents accidental drag/resize
  and field edits, not bulk operations. If you want stronger
  lock semantics ("locked slots can't be deleted either"),
  trivial to add.
