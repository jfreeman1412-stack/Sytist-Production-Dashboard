Phase 39 — Dashboard-driven package expansion

═══════════════════════════════════════════════════════
WHAT WAS WRONG
═══════════════════════════════════════════════════════

Order 110714 contained a Bronze Package (SKU 3) but processed
as a single 5x8 print instead of expanding into its constituent
items (4-3.5x5 Prints + 8 Wallets).

Root cause: Sytist's ms_cart.cart_package column is unreliable.
For this Bronze Package row, cart_package = 0 — the same value
used for plain (non-package) items. We confirmed this is a
pattern across the dataset, not a one-off.

The dashboard previously trusted flags.package (derived from
cart_package > 0) as the trigger to expand a package. Since
that flag is wrong, the expansion was skipped, and the package
header row got treated as a single regular print at the default
5x8 size.

═══════════════════════════════════════════════════════
THE FIX
═══════════════════════════════════════════════════════

Dashboard's Settings → Packages config is now the source of
truth for package detection. A line item is treated as a
package when its SKU has constituents configured there. The
unreliable flags.package signal is no longer consulted as the
trigger (though it's still surfaced in the line item shape for
informational purposes).

Pseudo-logic change in _expandPackageLineItems:

  BEFORE:
    if (!li.flags.package) skip;
    look up packageContentsMap[sku]
    if not found: pass through

  AFTER:
    look up packageContentsMap[sku]
    if not found: pass through (not a package)
    if found: expand
    (also log a warning when Sytist's flag was missing —
     so admins see the fallback firing)

═══════════════════════════════════════════════════════
EDGE CASES
═══════════════════════════════════════════════════════

  - SKU not configured in Settings → Packages: behavior
    unchanged — passes through as a regular line item.
  - SKU configured but with 0 constituents: passes through
    (the `length > 0` check protects against this).
  - SKU configured AND Sytist also flagged it correctly:
    expansion fires once, source='sytist_flag', no warning
    log, no UI banner.
  - Add-on items (Phase 15b/c) and package constituents
    (synthetic) never have an SKU that matches a package SKU,
    so this can't infinite-loop.
