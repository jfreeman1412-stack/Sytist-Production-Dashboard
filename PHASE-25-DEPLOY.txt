Phase 25 — Clip oversized slots to canvas (composite render fix)

═══════════════════════════════════════════════════════
THE PROBLEM
═══════════════════════════════════════════════════════

After Phase 21 (bleed support), slots can be sized or positioned
to extend past the canvas. The designer renders this correctly
because SVG naturally clips to viewBox bounds.

But the server-side composite engine uses sharp's composite()
operation, which REJECTS inputs larger than the destination
canvas with:

  Error: Image to composite must have same dimensions or smaller

So as soon as you tried to render a real order with a player photo
slot that bled past the canvas edge, the preview endpoint returned
500 and live preview broke.

═══════════════════════════════════════════════════════
THE FIX
═══════════════════════════════════════════════════════

Two new helpers in compositeService:

  _clipToCanvas(buffer, slotX, slotY, slotW, slotH, sheetW, sheetH)
    Crops a fitted slot buffer to the intersection of the slot
    rect and the canvas rect. Returns { input, top, left } with
    the cropped buffer and adjusted position, OR null if the slot
    is entirely outside the canvas.

  _clipDescriptor(descriptor, slotW, slotH, sheetW, sheetH)
    Wrapper for the { input, top, left } shape used by
    _placeholderSvg and _textSvg. Calls _clipToCanvas under the
    hood.

Every place that pushed a composite descriptor to the composites[]
array now runs through one of these helpers first. Eight call
sites total:

  - playerPhoto (image + placeholder)
  - playerBackground (image only — no placeholder for green-screen)
  - teamPhoto (image + placeholder)
  - logo (image + placeholder)
  - text (Phase 22's rotated text SVG can be larger than slot
    bounds; we read actual SVG metadata to clip correctly)
  - staticGraphic (image)

Behavior:
  - Slot fully inside canvas: fast path, no crop, identical to
    pre-Phase-25 behavior. No perf regression.
  - Slot exceeds canvas on any side: cropped to visible region
    using sharp's .extract(). Output looks exactly like the
    designer's trim-line preview.
  - Slot entirely off canvas: skipped silently. No error.
  - Negative slot positions (slot.x or slot.y < 0): cropped
    correctly using max(0, slotX) for the visible-region origin.
